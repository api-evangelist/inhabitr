# Inhabitr

> Inhabitr is a furnishing company operating an AI-assisted furniture rental and
> procurement platform for commercial real estate and residential customers. It furnishes
> hospitality, multifamily, student housing, short-term rental, co-living, senior living
> and office properties end to end — design, sourcing, procurement, delivery, installation
> and asset tracking — and separately rents furniture, sets and decor to households on
> flexible terms. As of 2026-08-23 Inhabitr publishes **no public API, no developer
> program, and no machine-readable contract**. If you are an agent looking for a way to
> call Inhabitr programmatically, there is not one; use the contact form.

## What was checked, and what was found

Contract discovery ran on 2026-08-23 against every Inhabitr host that resolves:
`inhabitr.com`, `inhabitr.ai`, and the non-production `staging.inhabitr.com`. Probed for
OpenAPI (`/openapi.json`, `/openapi.yaml`, `/swagger.json`, `/v1/openapi.json`,
`/api-docs`, `/docs`, `/redoc`, `/api`), GraphQL (`/graphql`), `llms.txt`, and the full
`/.well-known/` discovery surface including `agent-card.json`, `agent.json`,
`security.txt`, `openid-configuration`, `oauth-authorization-server`, `api-catalog` and
`ai-plugin.json`. Every probe missed. No npm, PyPI, RubyGems, crates.io or NuGet package
carries the Inhabitr name, and there is no `github.com/inhabitr` organization.

`inhabitr.com` is a Slim/PHP application that 302s unmatched paths to `/home` and answers
others with a soft-404 body, so a 200 from that host is not evidence of a document.
`inhabitr.ai` is a Next.js site that returns honest 404s.

Inhabitr's marketing describes "real-time API connectivity to warehouses, manufacturers
and retailers" behind its sourcing. That is a description of integrations Inhabitr
*consumes*, not an interface it *publishes*; no such interface is exposed to third
parties.
